# `josenimo/histo`: Contributing guidelines

This is a personal pipeline maintained by one person. There is no community contribution process, no
Slack channel, and no review rota. If you have found a bug or want to use this, open an issue.

## Where the conventions live

Deliberately not duplicated here, because duplicated guidance drifts:

- **[`CLAUDE.md`](../CLAUDE.md)** — the authoritative project context. Priorities,
  architectural decisions, module sourcing rules, container constraints, testing strategy, and the
  rules for agents operating on the HPC cluster. Where it conflicts with generic nf-core defaults,
  it wins.
- **[`AGENTS.md`](../AGENTS.md)** — the nf-core community agent guidelines, vendored verbatim.
  `CLAUDE.md` layers on top and takes precedence where they conflict.
- **[`ROADMAP.md`](../ROADMAP.md)** — the phased plan, the reasoning behind it, and the tracker.
  Open work goes in this file. GitHub Issues is enabled but unused.

## Before committing

Compliance comes from tooling, not from following guidelines by eye:

```bash
prek                        # formatting, linting, and the custom guard hooks
nf-core pipelines lint      # nf-core conventions
nf-test test tests/         # pipeline tests
nextflow run . -profile test -stub    # DAG and channel shapes, no containers needed
```

`-stub` is the primary fast feedback loop and the only one that works on an Apple Silicon laptop,
since the containers are amd64 only. **If you change a module's outputs, update its `stub:` block in
the same commit.** A stale stub that passes while the real run fails is worse than no test, and there
is a `stub-drift` pre-commit hook that enforces this.

Do not edit `nextflow_schema.json` by hand; use `nf-core pipelines schema build`. Do not edit nf-test
snapshots by hand; regenerate them.

## Use of AI and LLMs

Much of this pipeline is written with AI assistance. Humans remain responsible for the code
regardless of the tools used. The working rules:

- Keep commits small and single-concern.
- Avoid unnecessary changes, including moving or refactoring code, unless that is the explicit point
  of the commit.
- **Review all generated code and ensure you understand it before committing.** This matters more
  here than in most projects: an earlier version of this pipeline was assembled with AI assistance and
  without version control, and it contained a TMA dearray step that silently fabricated data when it
  failed. That defect survived because nobody read it.
- Disclose it. If an agent generated the majority of a commit, the commit message body ends with
  `Generated by <name>`.

The nf-core position on this is worth reading: [statement on AI](https://nf-co.re/blog/2026/statement-on-ai).
